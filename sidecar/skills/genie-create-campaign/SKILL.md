For Siswa Juara read `../genie-create-idea/references/editorial.md` and, for a multi-day plan, `../genie-create-idea/references/production.md`. Otherwise use the supplied brand context. Start from the stated objective, offer, audience, dates, channels, available assets, and team capacity. If dates are absent, use relative days; if product details are missing, label them rather than inventing an offer.

Give a coherent campaign idea and a manageable sequence of distinct posts. For each include proposed date/time zone (or relative day), channel/format, content segment, audience need, hook, actual caption or draft copy, one CTA, asset requirement, and draft/review status. Make a compact table for comparison and expand the copy only as needed. A date in a plan is a proposal, not a scheduled provider post.

Connect awareness, useful teaching, trust, and a relevant next action without forcing a funnel onto a simple announcement. Do not repeat the same exercise/hook across adjacent posts. Distinguish production dependencies from optional embellishment and identify missing evidence or review. Choose measurable outcomes and a realistic experiment without inventing performance data or claiming a universal best posting time.

Save a substantial plan as local `campaign.md` when useful, and summarize it in chat. Discuss mode leaves canvas.json untouched. If the user requests campaign artwork in Draw mode, use `../genie-create-carousel/SKILL.md` for each carousel, keeping its frames on the active canvas page and not overwriting other work. Do not invent a new page/project API. Planning does not authorize publishing, scheduling, sending messages, or accessing provider credentials. Direct the user to Publish to submit approved content using the app's website API.
