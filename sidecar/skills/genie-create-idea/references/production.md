# Production and planning details

These are adaptable practices from the two user-provided Word documents, not mandatory output fields for every request.

For a video package supply hook, chronological scenes, narration verbatim, screen text, answer/explanation if relevant, shot list, caption, and one CTA. Mark missing footage; never invent a timestamp in an unseen recording. For classroom clips, work from the actual supplied transcript and preserve speaker meaning while anonymizing private information.

Prefer tutor footage, handwriting, board work, and genuine screen recordings. Animation should explain the material. Vertical 9:16 suits the reference short-video workflow; keep text clear of platform interface areas and use subtle branding. Check audio/subtitle agreement, mathematical notation, spelling, and mobile readability. Respect supplied assets and licenses.

For batches, vary concepts, hooks, learning topics, and CTAs. Include effort and missing-asset status so a small team can produce the plan. One reference proposes a 14-day pilot at two posts daily before considering three; another proposes a parent-oriented mix of 40% tips/literacy, 25% exercises/explanation, 15% classroom activity, and 20% try-out/evaluation. These are optional hypotheses, not targets to impose. Proposed WIB morning/afternoon/evening slots are experiments, not proven best times. Follow the user's capacity, time zone, and actual insights.

Organize the work around idea, script, academic check, production, edit, final review, and publication preparation. Reserve 'scheduled' and 'published' for actual confirmed application/provider results. If real classroom footage is missing, substitute tutor explanation rather than invented student activity.

For evaluation choose metrics appropriate to the goal, such as completion, saves, useful comments, measured clicks, or registrations. Do not fabricate a baseline. Compare similar time windows; propose changing one main variable per A/B experiment.
