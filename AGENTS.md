# Working in Genie

Genie is a React/Vite editor with a Tauri desktop shell and a Node sidecar. The workspace contains Content, Canvases, Publish, Schedule, and Setting. Use `README.md` and the relevant guides under `docs/` for current workflows, and verify behavior against the implementation before updating instructions. The application no longer loads marketing skills; `sidecar/skills/` and `reference-skills/` are absent.

Preserve the local ownership model: a canvas has pages; a page contains frames. Canvases, versions, personal templates, saved drafts, content plans, and delivery receipts stay local. The document library uses SQLite on desktop and IndexedDB in the browser. Preserve canvas/page context and local edits across navigation. Keep existing canvas backups and legacy metadata readable without recreating chat records or assistant sessions. See `docs/storage.md` and `src/README.md` for storage boundaries and document contracts.

Content Studio lives in `src/content/`; `content/` remains the standalone source app. Tasks, questions, references, history, and task-to-canvas links use `genie.content.v1` in the local document library. Keep migration snapshots local and out of app builds. See `docs/content.md`.

Optional frame generation and narration rewriting use `@opencode/client` through the stateless text API. The current default is Beam Free, preferring `opencode-go`; unavailable models produce an error rather than a fallback. Generate composes blank branded scenes through validated declarative layers, typed diagrams, exact available asset references, and bounded choreography. The editor maps normalized layout/motion into geometry, assigns IDs, preserves branding/caption space, and owns document mutation. Story, look, and storyboard review precede motion preview, speech, and adding frames; closing scenes keep a siswajuara.com CTA. Legacy slot helpers remain compatible. Keep generation metadata local and retain editable review before adding frames. See `docs/ai-generation.md` and `docs/frame-context.md`.

ElevenLabs supplies speech, transcription, and account credit checks through the sidecar, with an explicitly selected billing account. Narration drafts, embedded audio, subtitles, and caption styles belong to frames and persist in canvas versions and backups. Saved frame templates omit those frame-level fields. Soniox remains reserved in configuration. See `docs/canvas.md` and `docs/animation.md`.

Social connections call Tebar directly for publishing, provider data, and usage. Saving a local draft or plan sends no provider request; publishing or provider scheduling requires explicit confirmation. Read actual usage from provider responses, distinguish request throughput from platform publishing quotas, and avoid recurring provider polling. See `docs/social.md`.

Store provider keys and related settings in local `config.json`, outside canvas exports and the library database; do not use the OS credential vault. Configuration includes `opencode`, `tebar`, `elevenlabs`, and reserved `soniox` settings. Desktop uses the application data directory; browser development uses the project root through Vite middleware. Public settings must omit secrets. Do not use the siswajuara.com API or website social tables.

Templates, illustrations, and animation catalogs are external asset packs under `asset-packs/`, excluded from app builds. Keep browsing lazy, remember the selected desktop folder in local `config.json`, and embed only placed media into local canvases so designs remain portable. See `asset-packs/README.md` for preparation and metadata.

`design-references/` is an authoring dependency, not a runtime dependency. Preset preparation reads its Classic, Studio, science, learning, and STEM source JSON and SVG ornaments. The STEM validation also reads its source JSON. The old reference-conversion layouts and source PNGs were removed; `text-layouts.json` and `artwork-layouts.json` are empty compatibility inputs, and cutout preparation currently has no artwork to process. Keep the active authoring sources available for rebuilding packs. Both `design-references/` and `asset-packs/` are Git-ignored local folders; a checkout alone does not supply them. See `design-references/README.md` and `scripts/prepare-presets.mjs`.

Keep verification focused on the affected behavior. Use the relevant local checks under `tests/`, affected Playwright specs, and `npm run build` for application changes; check Rust or staged sidecar packaging when those parts change. Mock providers: do not make live model calls, generate paid audio, publish posts, or run live provider mutations to test ordinary code changes.
